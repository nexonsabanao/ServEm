# ServEm Mobile

Flutter recreation of the ServEm mobile boards in `../ServEm/ServEm_Mobile-Design`,
connected to the same Firebase project as the web app and admin dashboard.

## Run

```bash
flutter pub get
flutter run                 # pick a device (web works with the bundled config)
flutter analyze             # currently: No issues found
flutter test                # 101 widget/navigation tests
```

The app opens on the Welcome screen. Log in or create an account to use Firebase; if the
current platform has no Firebase registration yet, the app automatically continues with the
local demo dataset so every screen stays explorable.

## Firebase

Native builds read the platform registrations generated by Firebase; no API key or app ID
is passed on the command line.

1. **Firebase console → Project settings → Your apps → Add app → Android**
   Package name: `com.servem.servem_app` (matches `android/app/build.gradle.kts`).
   Download `google-services.json` into `android/app/`.
2. **Add app → iOS** with bundle ID `com.servem.servemApp`, download
   `GoogleService-Info.plist` into `ios/Runner/`.
3. Optional: `flutterfire configure --project=servem-ph` regenerates both registrations.

4. **Authentication → Sign-in method**: enable Email/Password and Google. For native Google
   sign-in, add the Android SHA-1 certificate fingerprint in Firebase and use the downloaded
   `google-services.json` / `GoogleService-Info.plist`; on web, register the web OAuth client ID.
5. Deploy the Firestore rules and indexes from the web project once:

   ```bash
   cd ../servem_web
   firebase deploy --only firestore:rules,firestore:indexes --project servem-ph
   ```

### What syncs

| Action | Firestore |
| --- | --- |
| Sign up / sign in (email or Google) | `profiles/{uid}` (created with name, email, role) |
| Open the customer workspace | Reads the profile and bookings from Firestore |
| Confirm a booking | `bookings/{id}` + `notifications/{id}` |
| Log out | Firebase session cleared |

`lib/firebase/firestore_sync.dart` also exposes `saveMessage()` for chat sync. Everything is a
no-op when the user is not signed in or the platform has no app registration, so the demo flow
never blocks on the network.

## Structure

```
lib/
  app.dart                  session shell + root gate
  data/app_state.dart       demo data and local interactions
  data/demo_data.dart       board-transcribed content and models
  design/                   theme + shared widgets
  firebase/                 config, auth, Firestore sync
  screens/                  auth, customer, booking, bookings, messages, account, servmate
```

## Demo vs live

- Without a Firebase session the app runs entirely on `AppState` sample data.
- Signing in enables Firestore reads and writes for the profile and bookings. The mobile lists
  are populated from the signed-in customer's Firestore records after email or Google sign-in.
- Payments, payouts, verification and live location are simulated, as stated on the boards.
